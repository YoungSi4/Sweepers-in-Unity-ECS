# Timeout과 토큰 사용량 분석

## 현재 설정

| 에이전트 | 타임아웃 | 역할 | 입력 크기 |
|---------|--------|------|---------|
| **Planner** | 300초 | 코드 분석 (읽기만) | ~120자 (파일 경로) |
| **Reviewer** | 300초 | 계획 평가 (읽기만) | ~230자 (경로 2개) |
| **Coder** | **600초** | 코드 작성 (쓰기 필요) | ~320자 (경로 3개) |

---

## Coder만 증가시켜도 되는가?

### ✅ **YES — 완전히 가능하고 권장됩니다**

**이유:**

1. **Planner & Reviewer는 읽기 전용**
   - 분석, 평가만 수행 → 시간 소요 적음
   - 300초로 충분 (대부분 60~120초 내 완료)

2. **Coder는 실제 코드 작성 필요**
   - 계획 읽기 → 코드 작성 → 검증 → 정렬
   - 여러 항목(P1/P2/P3) 구현 시 시간 증가
   - 600초도 모자랄 수 있음

3. **독립적 타임아웃**
   - 각 에이전트는 독립적으로 실행
   - Coder의 타임아웃 증가가 Planner/Reviewer에 영향 없음

---

## 토큰 사용량 분석

### 타임아웃 vs 토큰 사용의 관계

```
타임아웃 증가 → 토큰 사용량 ??

답: 거의 관계 없음 (방향은 "최대 대기 시간"일 뿐)
```

**핵심**:
- **타임아웃**: 에이전트가 답변하기까지 기다리는 **최대 시간**
- **토큰**: 에이전트가 실제로 **입력 + 출력한 토큰 수**
- 에이전트가 60초에 완료되면, 600초 타임아웃은 의미 없음 (비용 동일)

### 토큰 비용 요소

```
총 토큰 = 입력 토큰 + 출력 토큰
```

**Coder의 경우**:

| 항목 | 비용 | 설명 |
|------|------|------|
| **입력 토큰** | ~400개 | 파일 경로 3개 전달 (매우 적음) |
| **출력 토큰** | ~2,000-4,000개 | 리팩터링된 코드 + 변경 사항 요약 |
| **Read 도구** | ~무료 | 에이전트가 직접 파일 읽음 (orchestrator 비용 무관) |
| **Edit/Write 도구** | ~무료 | 파일 수정 (orchestrator 비용 무관) |

**결론**: 
- Coder의 비용은 대부분 **출력 토큰(코드)**
- 타임아웃 증가 → 출력 토큰이 약간 증가할 **가능성** (더 상세한 설명)
- 하지만 일반적으로 타임아웃이 길어진다고 해서 토큰이 크게 증가하지 않음

## 권장 Coder 타임아웃 설정

### 기본 설정 (현재)
```python
timeout=600  # 10분
```

**대상**: 500줄 이하, P1-P3 항목 < 5개

### 보수적 설정 (권장)
```python
timeout=900  # 15분
```

**추가 토큰**: ~200-500개/실행 (가능성)  
**월 추정 비용**: 일 5회 실행 × 25일 × 350토큰 × $0.000003/token ≈ **$0.13**  
**장점**: 대부분의 경우 안정적

### 공격적 설정 (큰 파일)
```python
timeout=1200  # 20분
```

**추가 토큰**: ~500-1,000개/실행 (가능성)  
**월 추정 비용**: 일 5회 실행 × 25일 × 750토큰 × $0.000003/token ≈ **$0.28**  
**단점**: 정상적으로는 불필요 (토큰 낭비 가능)

### 이전 테스트 결과 (TestSystem.cs, 81줄)

```

Stage 1 (Planner)
  ├─ 실제 실행: ~45초
  └─ 타임아웃: 300초 (여유 많음)

Stage 2 (Reviewer × 2회)
  ├─ 실제 실행: ~60초/회
  └─ 타임아웃: 300초 (여유 많음)

Stage 4 (Coder)
  ├─ 실제 실행: ~90초
```

- Planner, Reviewer는 300초로 충분
- Coder도 600초로 완료
- 파일이 작으면 증가 불필요
